# A07 · 主干与可选模块能真正拆装

## 规范要求

宿主只依赖稳定契约。模块声明 ID、版本、能力、必需/可选依赖、页面与注册。Fluent API 表达组合，不意味着必须把所有类注册到容器。

## 为什么这样分

启动、许可工具、AI 管理及未来模块可以分别添加、移除和分发；UI 上隐藏不等于包里没有 DLL。

## 自动检查范围

部分自动：AT108 注册缺少 AtlasProvides；AT109 同一端口有多个不同提供方；AT110 只在能看见 AddAtlas 时，报告已声明却未注册的提供方；AT111 检查源码默认 ID 是否进入功能目录，不代表启动模块已经注册；AT118 报告绕过 AddAtlas 的容器注册。测试项目和 `ArchitecturalRole.Test` 里的注册是反例，不计入产品组合。`AtlasRegistration.AddScopedViewModel` 与 `AddResolvedProfile` 是已写明的组合入口：ViewModel 不是可替换端口，ResolvedProfile 是组合结果快照，二者不另走 AddAtlas。完全看不到注册时，不把“未注册”判成违规，也不把拆装判成已通过。另有架构 0.2 的 ModuleRegistry / ProfileResolver，在本宿主启动时校验显式父级、依赖闭包、能力接口和同主版本兼容；这些运行校验有独立正反例，不会凭静态报告自动判定已通过。目标模型对照写入同一份 AnalysisReport：没有模型或读失败是 AT122，严重级别为不支持，不能当成通过；源码模块不在模型中是 AT123，模型模块不见于功能目录是 AT124，跨顶层模块使用却没有声明依赖是 AT125，声明了能力却没有 AtlasProvides 是 AT126，实现了能力却没有写入模型是 AT127。同一顶层模块内部的嵌套引用不另记跨模块依赖。客户 DLL 分发闭包与热卸载仍未实现。

## 关联诊断

AT108, AT109, AT110, AT111, AT118, AT122, AT123, AT124, AT125, AT126, AT127

## 整理建议

先实现构建时可选组装与分发，验证删除模块后的剩余闭包。热插拔是单独能力，不要求首版实现；私有许可/AI 实现不能被公共入口强引用。

## 验收条件

公开包实际不含私有 DLL；移除可选模块后仍能构建启动；必需依赖缺失时报出明确原因。
