# A01 · 功能有层级，也有用途

## 规范要求

产品 → 功能模块 → 子功能/页面 → 职责 → 类型 → 操作。每个功能说明目的，每个方法说明输入、输出和作用；共享能力单独命名，不设包揽全部功能的 Core。

## 为什么这样分

几百个方法必须有上下文；技术职责不是全仓库的扁平菜单。

## 自动检查范围

部分自动：检查声明、层级、用途、参数与返回说明；无法自动证明归属合理。

## 关联诊断

## 整理建议

先列出真实用户任务与页面，再把类型和操作映射进去。尚未归属的代码进入待整理区，不能消失。

## 验收条件

每个功能能回答做什么、由谁触发、输入输出是什么；一个页面能独立查看它的状态、端口与用例。
