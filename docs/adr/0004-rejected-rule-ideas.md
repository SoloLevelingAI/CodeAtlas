# ADR-0004：暂不采纳的规则想法

状态：接受（明确拒绝以下想法）。日期：2026-10-18。

背景：模块协议和架构规范在字段稳定之前，容易把愿望写成诊断。下面三项曾被考虑，当前没有足够证据支持实现。

## 在协议有字段之前检查模块版本和依赖

当时的源码声明还没有版本、能力接口和依赖闭包。若先写“版本不兼容”或“依赖缺失”的静态规则，诊断只能对着不存在的字段猜测。现已由 `ModuleDescriptor`、`ProfileResolver` 和运行时正反例承担启动期校验；静态报告不把“没看见版本字段”判成违规或通过。

## 用 A05 证明纯度或归属

A05 要求状态和计算分开，AT102 / AT103 只能看见显式外部作用和已标注的契约。它不能证明一个方法在所有输入下都是纯函数，也不能证明功能归属命名正确。声明和目录位置都不是归属证据。

## 用 A09 做性能的静态检查

A09 约束的是历史、缓存和已测量的交互成本。静态源码不能回答任意规模下的耗时或内存。性能只保留本机对照测量，不新增“方法太慢”之类的规则。

后果：这些想法保持为文档中的拒绝项。若将来协议或测量证据变了，应新开 ADR，而不是把旧规则补成看似自动的认证。
